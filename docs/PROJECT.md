# Обзор ZeTer Photo Editor

ZeTer Photo Editor — локальный браузерный растровый редактор. Изображения обрабатываются в браузере; внешний сервер для обычной работы не нужен.

## Владельцы кода

- `index.html` и `src/styles.css` — структура и оформление интерфейса.
- `src/main.js` — контроллер UI, инструменты, ввод мыши/клавиатуры, история действий и файловые сценарии.
- `src/core/state.js` — документы, слои, безопасная нормализация проектов и embedded smart-object documents с ограничением вложенности.
- `src/core/render.js` — Canvas 2D-рендер и растровый экспорт.
- `src/core/pixel-worker.js` — bounded worker boundary для тяжёлых per-pixel цветокоррекций; Canvas/document state остаются на main thread.
- `src/core/pixel-buffer.js` — typed RGB/CMYK 8/16/32-bit adapter contract; текущий renderer получает из него только RGBA8 preview, а исходная precision может оставаться в typed buffer на внешней границе.
- `src/adapters/psd.js` — изолированный PSD/PSB adapter: RGB 8/16/32-bit importer/writer, version-aware 32/64-bit lengths, импорт/экспорт слоёв, каналов, Unicode-имён и bitmap masks; writer кодирует RLE построчно и собирает крупные sections chunk-wise.
- `src/core/layer-styles.js` — сохранение допустимых значений и Canvas-отрисовка стилей слоя.
- `assets/fonts/*/embedded.css` и `assets/fonts/*/OFL.txt` — локальные свободные шрифты и их лицензии; источники перечислены в [assets/fonts/README.md](../assets/fonts/README.md).
- Остальные `src/core/*.js` — геометрия, пиксельные операции, история, ввод-вывод, цвет и аварийное восстановление.
- `src/app.bundle.js` — генерируемая сборка для прямого запуска через `file://`; источник изменений находится в перечисленных выше файлах.

## Команды

Из корня проекта:

```text
npm run build
npm test
npm run check
npm run test:browser
```

`npm run check` пересобирает bundle, проверяет его синтаксис и запускает все Node regression-тесты. `npm run test:browser` запускает установленный Chrome/Chromium в headless-режиме через DevTools Protocol, открывает реальный `index.html` по `file://` и проверяет старт приложения, DOM-состояние блокировки слоя, guards меню и отсутствие runtime/console errors; при нестандартном расположении браузера можно задать `CHROME_BIN`. Для разработки через HTTP существует `npm run serve`; пользовательский запуск на Windows выполняется через `start.bat` или `index.html`.

## Критические границы

- Растровые кисти работают только с безопасно выделенным Canvas-буфером и публикуют результат в слой после завершения действия.
- Пока жест редактирования или асинхронная растровая операция не завершены, сохранение, экспорт, смена вкладки, замена документа и Undo/Redo отклоняются с просьбой повторить команду; экспорт использует отдельный снимок документа.
- Smart Objects Stage 5a: `embeddedDocument` является source of truth, `previewDataUrl` — только кэш отображения. Вкладка содержимого хранит `smartObjectLink` на родительскую session/layer; `Ctrl+S` обновляет embedded document + preview и добавляет одну запись в history родителя. Закрытие родительской вкладки блокируется, пока открыты дочерние content-tabs; lock родителя нельзя обойти через content-tab. UI и sanitizer ограничивают вложенность smart-object тремя уровнями.
- Linked Smart Objects Stage 11c: `smart-object.linkedSourceId` объединяет экземпляры одного внутрипроектного источника. Связанная копия сохраняет собственные layer-level transform/opacity/blend/masks/Smart Filters, но `saveSmartObjectContent()` публикует новый `embeddedDocument + previewDataUrl + width/height` всем слоям того же source ID одной history entry. Для группы используется одна content-tab на `parentSessionId + linkedSourceId`; unlink обнуляет source ID, не удаляя текущее embedded содержимое. Это не внешний файловый link: browser/file:// lifecycle и permission semantics внешних ресурсов требуют отдельного этапа.
- Smart Filters Stage 11a: `smart-object.smartFilters` — отдельный bounded ordered stack (max 24), не смешанный с outer `layer.filters`. UI показывает stack top-first, renderer идёт по нему bottom-up; каждый enabled entry сначала выполняет advanced RGB corrections через существующий Pixel Worker, затем basic Canvas/CSS filter pass. `smartFilterCache` ключуется по `previewDataUrl + stack signature`, а outer adjusted-raster cache также включает stack signature, чтобы reorder/edit/content update не отдавали stale pixels. Dialog мутирует draft для live preview, Cancel полностью восстанавливает исходный stack, Apply создаёт одну history entry.
- Pixel Worker Stage 6a: крупный advanced-color RGBA loop может выполняться вне main thread через Blob Worker. Очередь bounded, buffer transferable, ошибки/timeout сбрасывают worker; renderer перечитывает Canvas и использует sync fallback, если transferred buffer уже detached. Worker не владеет document/Canvas state и не загружает внешний script, поэтому `file://` остаётся поддерживаемым.
- PSD Stage 4 — ограниченный RGB/8-bit round-trip: text/shape/transforms/filters/styles растрируются в per-layer preview, groups flatten, bitmap masks сохраняются отдельным user-mask channel. При видимых adjustment layers экспорт добавляет верхний composite preview и скрывает исходные PSD layers, чтобы при открытии сохранить итоговый вид без ложной native Photoshop adjustment-семантики.
- PSD Writer Stage 6b не создаёт full-size channel planes: RLE lengths измеряются по строкам и rows повторно кодируются прямо в chunked writer. Это сознательный memory-first trade-off перед streaming/PSB.
- PSD Blob Stage 6c: UI использует `encodePsdBlob()` и строит Blob прямо из writer chunks; `encodePsd()` остаётся byte-array compatibility API. Это убирает обязательную финальную contiguous-копию в browser download path.
- PSB Stage 7a: adapter принимает version 2 и пишет/читает PSB 64-bit Layer/Mask, Layer Info и channel lengths. Stage 12e добавляет native `Lr16/Lr32`, Stage 13b — native CMYK color mode 4 и 5-channel composite. Safety limits сохраняются.
- PixelBuffer Stage 7b: PSD/PSB adapter возвращает `pixelBuffer` как typed raster payload и совместимый `pixels` alias для RGBA8. RGB 16/32-bit source сохраняется в `.zpe` через Stage 12a, участвует в high-depth render/edit через Stage 12b/12d и может идти напрямую в writer Stage 12e. Stage 13a активировал существующую CMYK typed-модель: 4/5-channel 8/16/32-bit CMYK сохраняется canonical source и получает отдельный color-management preview path.
- High-depth Raster Source Stage 12a: `serializePixelBufferSource()` кодирует typed samples в canonical little-endian binary data URL, raster layer хранит optional `highDepthSource`, а sanitizer проверяет payload bounds/shape. PSD/PSB import распределяет общий raw budget 48 МБ между 16/32-bit layer sources. Canvas `dataUrl` остаётся preview/fallback proxy; Stage 12d обновляет source напрямую для поддержанных destructive tools, а только Canvas8 fallback обязан снять устаревший `highDepthSource`.
- High-depth Render Bridge Stage 12b: `pixelBufferToToneMappedRgba8Preview()` читает сохранённые `Uint16Array`/`Float32Array` samples, делает exposure/gamma/temperature/tint/vibrance/highlights/shadows до display conversion и не мутирует source. `render.js` предпочитает этот bridge для raster `highDepthSource`, кэширует не больше двух decoded buffers и пропускает старый RGBA8 advanced-pass. Float32 `linear-*` получает ACES-style tone map + linear→sRGB; 16-bit `srgb` — linearized correction + clip. Stage 12d уже даёт native typed base editing, Stage 12e — native high-depth writer; Canvas8 остаётся display/fallback boundary, не полноценным high-depth Canvas.
- HDR Preview Controls Stage 12c: raster `highDepthPreview={toneMap,displayExposure}` хранится только при валидном `highDepthSource`; sanitizer разрешает `auto|clip|aces` и EV `[-6,+6]`. Render cache key включает оба display-параметра. `pixelBufferToToneMappedRgba8Preview()` применяет display EV после layer high-depth corrections и до выбранного tone map; Auto = Clip для 16-bit и ACES для 32-bit. Stage 12d сохраняет source при поддержанных typed edits; settings очищаются только при реальном переходе на Canvas8 fallback.
- Native High-depth Editing Foundation Stage 12d: `pixel-buffer.js` содержит typed destructive primitives для RGB PixelBuffer: deep clone, optional straight-alpha upgrade, brush dab/stroke source-over, eraser alpha reduction, flood fill и predicate-based clear. `main.js` держит отдельный high-depth working buffer и публикует tone-mapped preview через raster override с `skipAdjustments`; commit сериализует source обратно в `.zpe`. Line/fill/selected clear/cut-all используют one-shot typed mutations. Общий 48 МБ raw budget остаётся инвариантом; alpha-upgrade, который не помещается, не маскируется — операция откатывается на Canvas8 boundary.
- Native 16/32-bit PSD/PSB Export Stage 12e: writer принимает global `bitsPerChannel` и per-layer `pixelBuffer`; 8-bit остаётся PackBits/RLE, 16/32-bit channel payload пишется Raw big-endian напрямую из typed samples. Layer records high-depth документов вынесены из ordinary Layer Info в document-level `Lr16` / `Lr32`; PSB применяет `8B64` и 64-bit tagged length. Decoder получил симметричный scanner этих blocks. Export planner отдаёт native source только для identity raster geometry без filters/styles; mixed raster previews widen до общей глубины с warning. Stage 12g заменяет прежний single-layer-only `compositePixelBuffer` shortcut настоящим typed multi-layer compositor для совместимой семантики.
- Typed High-depth Retouch Stage 12f: high-depth paint state теперь обслуживает не только brush/eraser, но и blur/clone/heal/smudge/dodge/burn. `pixel-buffer.js` делает retouch в linear working RGB поверх исходных typed samples: exposure-based dodge/burn, alpha-weighted local blur, immutable-snapshot clone с bilinear sampling, healing с neighborhood gain adaptation и directional smudge. Stroke coverage не даёт blur/tone многократно усиливаться на перекрывающихся dab одного штриха; selection predicate применяется в layer coordinates. Live preview остаётся 8-bit tone-mapped raster override, но canonical source до commit остаётся `Uint16Array`/`Float32Array`.
- High-depth Multi-layer Composite Stage 12g: `compositePixelBufferLayers()` выполняет positioned straight-alpha blend в typed RGB, поддерживает восемь ZPE blend modes, layer opacity и RGBA bitmap-mask coverage. Export planner повторяет group ordering renderer-а для pass-through/100% groups, смешивает native 16/32-bit и rasterized RGBA8 sources без понижения всего composite до 8-bit и передаёт результат как `compositePixelBuffer` в PSD/PSB writer. Target 32-bit использует linear working space с sRGB→linear conversion для 8/16-bit inputs. Vector masks, adjustment layers и isolated group semantics пока намеренно переключают merged image на Canvas8 fallback. Output allocation ограничен 256 МБ.
- CMYK / ICC Preview Foundation Stage 13a: PSD/PSB color mode 4 принимает 8/16/32-bit C/M/Y/K(+alpha) и хранит Photoshop-inverted storage как внутренний ink-space PixelBuffer. Базовый ICC path поддерживает `mft1/mft2` A2B LUT и sRGB display preview.
- Advanced ICC + Native CMYK Round-trip Stage 13b: ICC core дополнительно разбирает `mAB ` A/CLUT/M/Matrix/B и float `mpet` `D2B*` для `clut`/`matf`; document schema хранит rendering intent/display policy. Writer принимает `colorMode=4`, пишет инвертированные C/M/Y/K, alpha, native 8/16/32-bit samples и ICC resource. `compositeCmykPixelBufferLayers()` строит bounded 5-channel merged composite для Normal/pass-through stack с opacity и bitmap masks. Unsupported MPE elements и несовместимая layer semantics fail-safe оставляют явный fallback. Native CMYK destructive/retouch, full `cvst`, custom display profiles/BPC/soft proofing относятся к Stage 13c+.
- RGB 16-bit Import Stage 7c: PSD/PSB layer/composite channels с глубиной 16-bit декодируются как big-endian samples в `Uint16Array`. Raw, PackBits/RLE и ZIP поддержаны; Stage 12a сохраняет source в `.zpe`, Stage 12d добавляет typed base editing, Stage 12e экспортирует compatible channels как native 16-bit, Stage 12f сохраняет 16-bit precision при retouch. Transforms/effects могут входить в Stage 12g composite как уже rasterized 8-bit preview; unsupported group/vector/adjustment semantics всё ещё могут перевести merged image на Canvas8 boundary.
- RGB 32-bit Float Import Stage 7d: PSD/PSB 32-bit/channel samples читаются big-endian как IEEE-754 `Float32Array`; Raw, RLE и ZIP поддержаны для layer/composite channels. Stage 12a сохраняет Float32 source в `.zpe`, Stage 12b выполняет high-depth exposure/color, Stage 12d сохраняет HDR headroom в базовых destructive tools, Stage 12e пишет Float32 HDR channels обратно в PSD/PSB, а Stage 12f переносит retouch в typed HDR path. Stage 12g уже даёт high-depth multi-layer merged composite для совместимой семантики; следующим imaging-этапом остаётся ICC-managed conversion/CMYK.
- High-depth ZIP Prediction Stage 7e: compression=3 decoder использует depth-specific inverse predictor: byte delta для 8-bit, 16-bit word delta для big-endian samples и Photoshop byte-plane unshuffle после delta decode для 32-bit floats. Один helper обслуживает layer и composite paths. `inflateZlib()` читает `DecompressionStream` chunk-wise и прерывает поток при превышении заранее рассчитанного output ceiling, уменьшая риск memory amplification на повреждённых/враждебных ZIP-каналах.
- ICC Metadata Foundation Stage 7f: Image Resources parser читает `8BIM` blocks с Pascal-even names/data padding, извлекает resource 1039 как raw ICC bytes (hard cap 4 МБ) и resource 1041 как intentionally-untagged flag. Минимальный adapter header parser проверяет declared size, version, device class, color space, PCS и `acsp` signature. Stage 13a использует raw bytes уже не только как metadata: отдельный color-management core строит поддерживаемый CMYK device→PCS transform.
- ICC Metadata Round-trip Stage 7g: document schema хранит bounded `colorProfile`; writer формирует resources 1039/1041. Для RGB это остаётся metadata preservation; Stage 13a/13b используют CMYK profile для display transform, а Stage 13b передаёт тот же profile вместе с native CMYK writer output.
- PSD/PSB Group Import Stage 8a: первый group-import этап интерпретирует `lsct` type 1/2 как open/closed folder и type 3 как hidden bounding divider, собирает group path стеком и передаёт `groupKey` на bitmap layers. Историческое flatten `Parent / Child` относилось только к Stage 8a; Stage 8c ниже заменил его настоящей `parentGroupId` hierarchy.
- PSD/PSB Group Export Stage 8b: базовый writer разворачивает group runs в hidden bounding divider + folder `lsct` records и отдельно сохраняет folder/child visibility. Ограничение flat metadata было снято Stage 8c, который добавил nested lineage writer; `PSD_EXPORT_GROUP_SPLIT` остаётся guardrail для структурно некорректного re-entry.
- Nested Groups Stage 8c: `createLayerGroup()` и `.zpe` schema поддерживают optional `parentGroupId`; sanitizer удаляет orphan/self/cyclic parent links, а visibility/locking вычисляются по всей ancestor chain. Удаление группы переподключает прямые слои и child groups к её родителю, не выбрасывая содержимое. Layer panel рекурсивно показывает hierarchy и ancestor hidden/locked state. PSD/PSB adapter передаёт `parentKey`, import создаёт настоящую ZPE hierarchy, export строит nested `lsct` transitions и отклоняет re-entry/cycle/missing-parent вместо неверного файла.
- Nested Groups UX Stage 8d: layer panel имеет отдельный `groupDragId`; unlocked group row draggable и принимает другую группу через `moveLayerGroupIntoGroup()`. Drop на свободную область панели поднимает группу в root, контекстное меню создаёт подгруппу напрямую. State-level cycle/ancestor-lock validation остаётся единственным source of truth, поэтому UI не может обойти structural guards.
- Select & Mask Foundation Stage 9a: `refineMaskAlpha()` в `src/core/pixels.js` выполняет deterministic 8-bit mask refinement без внешних библиотек: binary smooth, grow/shrink через separable max/min morphology, feather через два separable box-blur passes, edge contrast и invert. UI растеризует текущую selection shape в координаты слоя, масштабирует px-параметры относительно transform scale и создаёт/заменяет layer mask. Refinement path ограничен 12 МП; обычная маска из выделения остаётся доступной для больших документов.
- Select & Mask Preview Stage 9b: generic modal получил безопасный `onMount` hook, а refinement dialog подключает reduced-resolution live preview без изменения document/history. Source selection растеризуется максимум примерно в 420×240 preview buffer; те же параметры переводятся из document px в layer px и затем в preview scale. Input/change коалесцируются через `requestAnimationFrame`, cleanup отменяет pending frame и listeners при закрытии.
- Select & Mask Edge Detection Stage 9c: `refineMaskEdgeAware()` строит binary rough mask, eroded foreground core и dilated boundary band. Для band pixels он ищет confident foreground/background samples по 8 направлениям, сравнивает RGBA distance и смешивает rough alpha с data-driven target. `smartRadius` дополнительно масштабирует влияние по color-separation confidence. Source RGBA для raster/text/shape/smart-object строится из unmasked local layer render; adjustment mask использует current document composite. Final edge work ограничен `pixels × radius <= 48M`, а live preview работает на bounded reduced buffer. Это heuristic edge detector, не Photoshop parity.
- Select & Mask View Modes Stage 9d: preview presentation отделена от mask algorithm. Pure `composeMaskPreviewRgba()` строит B/W mask, red overlay, black-background и white-background views из одного `sourceRgba + refinedAlpha`; UI field `viewMode` не входит в `selectionRefineOptionsFromValues()`, поэтому смена вида не может случайно изменить финальную маску.
- Vector Masks Stage 10a + Path Operations Stage 10b: `baseLayer` получил optional `vectorMask`; sanitizer ограничивает маску 128 subpaths × 2000 nodes и нормализует `add/subtract/intersect/exclude`. Renderer создаёт локальный vector-mask bitmap только на mask boundary: `source-over`, `destination-out`, `destination-in`, `xor` реализуют boolean subpaths, затем vector mask и raster mask последовательно пересекают isolated layer content. UI переводит document selection в layer-local coordinates; ellipse сохраняется четырьмя cubic Bézier nodes с kappa handles. Маска сохраняется в `.zpe`, поддерживает enable/invert/remove и selection-driven Replace/Add/Subtract/Intersect/Exclude. PSD writer пока не создаёт Photoshop vector-mask resource: визуальный результат попадает в raster preview и сопровождается warning.
- Vector Mask Direct Edit Stage 10c: existing Pen direct-edit abstraction расширен с shape `pathPoints` до typed targets (`shape` / `vector-mask`). Vector-mask edit mode показывает все subpaths выбранной маски, hit-test сначала handles, затем anchors; drag хранит `pathSource + subpathIndex`, поэтому pointer cancel/restore и history применяются к правильному контуру. Переключение с Pen сбрасывает mask edit mode; blank click во время редактирования маски не создаёт случайный shape path.
- Native PSD/PSB Vector Masks Stage 10d: adapter реализует официальный `vmsk` container (version 3 + flags) и общий 26-byte Photoshop path-record codec. Fixed-point 8.24 coordinates переводятся относительно document width/height; knot record хранит incoming control / anchor / outgoing control, linked selectors мапятся на `smooth`. Boolean op map совместим с распространённой Photoshop/ag-psd семантикой: exclude=0, add/combine=1, subtract=2, intersect=3. Export рендерит layer pixels с `vectorMask=null` и отдельно пишет native mask, поэтому маска не применяется дважды. Unlinked flag сохраняется, но ZPE transform UX пока всё ещё двигает mask вместе со слоем — это явно предупреждается.
- PSD/PSB Saved Paths Stage 10e: Image Resources IDs `2000..2997` используют тот же path codec и сохраняются как bounded `document.paths` (до 998 ресурсов, 128 subpaths × 2000 nodes после `.zpe` sanitize). Saved paths не участвуют в Canvas render и поэтому round-trip не меняет изображение.
- Paths Panel Stage 10f: правая collapsible panel рендерит `document.paths` как отдельные document-level сущности, а не псевдослои. UI selection хранится в document session (`selectedPathIndex`), поэтому вкладки не перетирают выбор друг друга. `pathFromCurrentSource()` сохраняет vector mask / shape path / selection без rasterization; `applySelectedDocumentPathAsVectorMask()` делает обратное document→layer-local преобразование. Pen target abstraction получил третий source `document-path`; для него control points уже находятся в document coordinates, поэтому drag не применяет layer transform. Context menu и keyboard ArrowUp/Down поддерживают навигацию. Adjustment layer пока намеренно исключён из команды «path → vector mask», потому что его mask coordinate contract требует отдельного этапа.
- Group Compositing Stage 8e: group schema хранит `opacity` и `blendMode` с default `pass-through`. Renderer строит hierarchy plan по `parentGroupId`/layer order: 100% Pass Through не создаёт лишний bitmap и пропускает children прямо в parent stack, а reduced-opacity/non-pass-through group получает isolated full-document Canvas и затем композитится с group alpha/blend. Это также ограничивает adjustment layers внутри isolated group её собственным буфером; pass-through adjustment может воздействовать на уже отрисованный parent stack. PSD/PSB folder record переносит opacity и section blend key в обе стороны. Сложные edge-cases Photoshop compositing всё ещё требуют real-file compatibility suite.
- Стили слоя хранятся отдельно от исходных пикселей в `.zpe`; окно «Параметры наложения» показывает черновик, отмена восстанавливает прежние значения, применение создаёт одно действие истории. Временные Canvas для стилей ограничены 16 МП; на очень больших слоях предпросмотр и экспорт стилей используют пропорциональное уменьшение для защиты памяти.
- В окне «Параметры наложения» для общих настроек и каждого стиля виден фрагмент итогового холста вокруг слоя. Он копируется после завершённой отрисовки и меняет размер вместе с окном; окно растягивается за нижний правый угол.
- После асинхронного чтения изображения, проекта или буфера обмена операция проверяет исходную вкладку и документ; результат не переносится в другую вкладку. Открытие проекта также отменяется, если за время чтения изменился текущий документ, даже до записи правки в историю. Растеризация дополнительно проверяет, что выбранный слой не изменился до публикации результата.
- Разрушающие растровые инструменты редактируют только текущий выбранный, видимый и незаблокированный растровый слой; они не должны молча переключаться на другой слой под курсором.
- Штамп и лечебная кисть берут неизменяемый снимок источника на начало штриха, чтобы результат не копировал сам себя.
- Осветлитель и затемнитель меняют RGB существующих пикселей с мягким спадом силы, не создают пиксели на прозрачном фоне и не меняют alpha. Сила каждого инструмента задаётся отдельным ползунком; повторные отпечатки в одном штрихе ограничены максимальным воздействием на пиксель.
- Штамп, лечебная кисть, смазывание и локальное размытие используют растушёванный край; сила локального размытия задаётся процентами за штрих и также не накапливается от перекрывающихся отпечатков. Магнитное лассо уточняет промежуточные точки между кликами.
- Волшебная палочка ограничена документами до 8 МП для предсказуемого расхода памяти.
- Состояние проекта хранится в `.zpe`; загрузчик принимает текущую версию v1 и совместимый legacy JSON без поля `version`, но отклоняет неизвестные версии вместо их молчаливого преобразования. Аварийное восстановление использует IndexedDB: каждое окно хранит отдельный снимок всех своих несохранённых вкладок, а при запуске доступны все копии, включая старый одиночный формат. «Позже» оставляет найденные копии без удаления. Скачивание `.zpe` через браузер не подтверждает, что файл появился на диске; до проверки файла вкладка остаётся помеченной несохранённой.
- «Размер изображения» проверяет преобразования всех слоёв до изменения документа и отклоняет размер, при котором повторное открытие `.zpe` обрезало бы координаты или масштаб слоя.
- Node-тесты не доказывают внешний вид, реальные pointer-события или Clipboard API. Автоматический browser smoke теперь доказывает базовый Chromium `file://` startup и критический lock/unlock DOM-contract, но визуальная геометрия, pointer/drag-жесты, Clipboard API и другие browser-specific flows по-прежнему требуют отдельного browser/manual proof.
- Текстовый диалог показывает черновик на холсте через отдельный render-документ; малый предпросмотр копирует тот же фрагмент холста в месте текста, включая фон изображения. До «Добавить»/«Применить» исходный документ, история и восстановление не меняются; «Отмена» убирает черновик. Окно перетаскивается за заголовок, размер окна и малого предпросмотра меняется за угол.
- Встроенные WOFF2-шрифты подключаются локально при выборе. Свой WOFF/WOFF2/TTF/OTF до 5 МБ встраивается в `.zpe`; список шрифтов компьютера запрашивается кнопкой через Local Font Access API и зависит от браузера и разрешения пользователя.
