## Why this is the next bounded production task
003X/5 removed a full binary-string join in Base64 conversion and made multi-victim dirty LRU eviction all-or-nothing on encoder failure. canonicalTileBytes in src/core/pixel-buffer.js can still allocate full canonical raw byte arrays, bytesToDataUrl and serialized concatenation may duplicate large strings, and writer/History/Worker ownership is not globally bounded. Neither decoded tile-cache budget nor encoded dirty-overlay reservation is equivalent to transient memory or process RSS. Find one reproducible owner-specific amplification or correctness failure before modifying production code.

1. Read actual src/core/pixel-buffer.js, src/core/io.js, their callers in serialization, import/export, History and Worker. Trace raw bytes, string construction and GC eligibility through synchronous makeRoom, publishStaged, serializeSteps and cancellation. Distinguish resident typed bytes, retained dirty overlays, one-shot encoding buffers, JS strings and browser process memory; name which are measured vs estimated.
2. Establish a failing or resource-accounted regression with actual native high-depth RGB16 and CMYKA32 Float32 bytes (preserve alpha and Float32 bit representations). Include sparse and dense tiles, edge tiles, repeated dirty edits, second/later encode failure and refusal before published state mutation.
3. Deliver a minimal production change to reduce or cap demonstrable transient copies: explore direct chunked canonical encoding, preflight sizing before raw allocation, or incremental bounded URL construction where supported. Do not add a default cap that unexpectedly breaks valid dense documents; fail closed under an explicit limit. Avoid unrelated new dependencies, mandatory server, lossy 8-bit conversion or promise of streaming where API requires a full data URL.
4. Prove atomic rollback when encoder throws, allocation budget is exceeded or cooperative operation is cancelled/stale. Preserve exact Undo/Redo, .zpe v1/v2 compatibility and high-depth PSD/PSB native values. Do not alter an earlier dirty tile or cache LRU order on a later failure.

Include failure injection and independent source-byte verification; state any blocked Photoshop-authored PSB32 evidence without substituting synthetic PSD.
6.
